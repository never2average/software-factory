How to get in

A person

https://onfinance-hfc.vercel.app — sign in with a six-digit code emailed to you, or Continue with Google where the workspace uses it. Access is by workspace membership: the owner invites people from Workspace → People.

An agent, hosted

Any MCP-capable assistant connects to https://onfinance-hfc.vercel.app/api/mcp with the person's own access token as a Bearer header. The token comes from the same emailed code and lasts 7 days; it proves an email address, and access still follows workspace membership.

An agent, by package

@onfinance/hfc-research — built and checked, not published yet (waits on the operator's npm sign-in). npx @onfinance/hfc-research login --email you@company.com, then … mcp.

Address

Lives at its Vercel address. No own domain is named yet; choose one before the package is first published, because the address is baked into it.

Rules of the road

  1. Start from python3 .claude/scripts/mint.py onfinance_hfc. It shows every station and the one next step; run does whatever needs nobody. Do not drive the station scripts by hand.
  2. The mold is a general-purpose snapshot. This product's own code is its pack (packs/hfc-research/). A change to base behaviour is a pull request upstream, never a fork.
  3. Credentials are named, never shown: not in the repository, not in a chat, not on this page. A pasted sign-in code becomes a private session outside the repository.
  4. The operator is not an engineer. Ask for one thing at a time, in plain words, with numbered clicks from a web address, and say what is hidden and what expires.
  5. Never publish a package, send a sign-in code to a real person, or create paid resources for a new application without the operator saying so.
  6. Report what was measured. Read a test report before describing its result; a failed lane marks the application reverted until the cause is fixed and the ordered run passes.
